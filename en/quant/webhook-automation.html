4.5 TradingView Webhook 直連 API 自動化下單

回測出優秀的量化策略後，最關鍵的一步就是實現「零人為干預的全自動下單」。本單元將為您示範如何利用 TradingView 的 Webhook 警報，發送加密 JSON 訊號直連券商與交易所 API 執行自動交易！

章節一：Webhook 自動化架構與運作原理

Webhook 是一種在應用程式之間傳遞實時數據的 HTTP 回呼 (HTTP Callback) 機制。當 TradingView 圖表觸發訊號時，會以 POST 方式發送 JSON 數據至伺服器。

全自動連線架構圖：

[ TradingView 策略訊號 ]
↓ (HTTP POST / Webhook JSON 訊號)
[ 中繼伺服器 Python Flask / Webhook Gateway ]
↓ (簽名認證 HMAC SHA256 / API Secret)
[ 交易所 API：Binance / OKX / 盈透證券 IBKR ] ➔ 自動開倉/平倉

章節二：Pine Script 警報與 JSON Payload 配置

在 Pine Script 程式碼中使用 alert() 函數動態傳送買賣方向與部位數量：

// Pine Script v5 範例 if (longCondition) alert('{"action": "BUY", "symbol": "BTCUSDT", "qty": 0.05, "type": "MARKET"}', alert.freq_once_per_bar_close) if (shortCondition) alert('{"action": "SELL", "symbol": "BTCUSDT", "qty": 0.05, "type": "MARKET"}', alert.freq_once_per_bar_close)

在 TradingView 建立警報時，勾選 Webhook URL，輸入伺服器網址（例如 https://your-server.com/webhook），即可實現微秒級自動觸發。

本單元實戰觀念隨堂測驗

Q1. 在進行 24 小時 Webhook 自動化交易時，確保 API 安全性的最重要措施是什麼？

A. 將 API Secret 金鑰公開貼在網路上供社群驗證
B. 設定交易所 API IP 白名單、關閉提現 (Withdrawal) 權限，並對 Payload 進行 HMAC 簽名
C. Webhook 傳輸不需要任何安全措施
解析正確！ 量化交易 API 金鑰嚴禁開啟「提現權限」，且伺服器應綁定 TradingView 固定 IP 白名單並進行 HMAC 加密簽名，防止偽造訊號攻擊。

Q2. 為什麼在 Pine Script 警報中建議使用 `alert.freq_once_per_bar_close`（K 線收盤才觸發）？

A. 防止 K 線在未收盤前因為價格閃爍造成重複發送過度下單 (Repainting/Over-trading)
B. 為了讓交易所可以多收幾次手續費
C. K 線收盤觸發會導致手續費變便宜
解析正確！ 盤中 K 線尚未收盤時，指標可能產生虛假訊號（未來函數/Repainting）。在收盤時確認觸發能確保下單訊號與回測結果百分之百一致。

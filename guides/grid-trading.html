CHAPTER 01 / GRID FOUNDATIONS

動態網格的核心：不是保證套利，而是預先管理區間庫存

買低賣高的階梯規則

現貨網格將下限 L 到上限 U 切成 n 個價格層；價格向下穿越層級時配置買單，向上穿越時配置賣單。策略的收益來自區間內多次完成回合，代價是必須持有報價幣與基礎資產，並承擔出界後的單邊庫存。

兩種層級結構

等差層級 P_i=L+i(U−L)/n，每格固定 USDT 價差；等比層級 P_i=L×(U/L)^(i/n)，每格維持近似比例差。等差容易用固定金額管理，等比適合用百分比衡量波動；選擇前先決定要控制哪一種風險。

Worked example

BTC/USDT 區間 70,000–85,000、30 格等差，每格價差 500。若價格在 77,500 附近，毛間距約 0.645%；但買賣雙邊各 0.1% 手續費後只剩約 0.445%，再扣滑價與最小下單量後才是較接近實務的單格結果。

盲點

網格成交筆數不等於淨利；急跌會連續買入並留下下跌資產，急漲會賣光現貨後錯過上行。啟動前先定義出界後是否停機、轉換或重新設定。

CHAPTER 02 / GRID FORMULAS

網格計算：單格利潤、費用、資金利用率與回撤不能分開看

把雙邊成本扣進去

等比費後間距可近似為 (P_(i+1)/P_i−1)−2f；等差則以價差除以成交基準價，再扣雙邊費率 f。若毛間距不大於費用與滑價，增加網格只會增加執行次數，不會增加有效收益。

現金、基礎資產與掛單

資金利用率可先用 已配置資金÷總投資額 觀察，但實際還要分開現金、已持有基礎資產、未成交掛單與已實現利潤。利用率越高不代表越好，因為剩餘緩衝越少，出界與追加資金壓力越大。

Worked example

總資金 10,000 USDT，若分配成 40% 現金與 60% BTC，單格配置約需依價格層和網格數分拆。當 10 格買單連續成交時，現金可能快速下降；模型要顯示期末 BTC 庫存，而不是只顯示已完成賣出回合。

盲點

不要把回測中的「毛套利」當作淨報酬；手續費、滑價、資金費、提款和轉帳成本都可能使小間距策略失效。

CHAPTER 03 / GRID PRACTICE

網格實戰設定：用長短週期 K 線檢查區間，而不是用希望決定上下限

建立候選區間

先用較長週期辨識高低位和市場狀態，再用近期波動、支撐與壓力建立候選上下限。區間要寫出失效條件，例如日線收盤跌破下限、波動率持續上升或基本面事件改變，而不是只選一個心理價位。

參數不是越多越好

等差可讓每格絕對價差直觀，等比讓每格比例接近；網格太密使最小下單量和費用占比上升，太疏則可能錯過震盪。用實際交易所規格檢查每格是否能成交。

回放要看什麼

使用 K 線回放記錄成交回合、期末庫存、資金利用率、最大回撤、觸及邊界的次數和出界後表現。只看總利潤會掩蓋最後仍持有的大量下跌資產。

執行清單

啟動前確認交易對、區間、格數、模式、總資金、費率、最小下單量、停損、止盈、停機與重新配置規則。

CHAPTER 04 / GRID RISK

破網風險：單邊趨勢、流動性與停機規則決定網格能否活下來

兩種不同的庫存問題

下破會持續消耗報價幣並累積基礎資產；上破會持續賣出基礎資產並可能錯過趨勢。兩者都需要明確的 stop、take-profit、停機和資產處理。

壓力案例

若 BTC 由區間中位數急跌 20%，網格可能在短時間填滿買單；即使每格都曾有套利，期末庫存的市值損失仍可能大於已實現利潤。回撤應用總資產計算，而不是只看現金帳。

交易所與操作風險

API 權限、斷線、撮合延遲、提款限制、清算、交易所信用和穩定幣脫鉤都可能造成策略偏離。不要給不必要的提款或交易權限，也不要把所有資產留在單一平台。

檢查頻率

每日或每週檢查價格距離邊界、庫存偏斜、已實現／未實現損益、費後間距和市場狀態。若原始震盪假設失效，停止策略比加碼更符合風控。
